# Vendored specifications

Copies of the specifications playerctl implements, pinned to a revision so the code can be checked against them offline. Every set has a `SOURCE` file with its URL, revision and license. Do not edit the files by hand: change the pinned revision in `scripts/vendor-specs.sh` and run `make vendor-specs`.

The MPRIS files are byte-identical to upstream, as are the D-Bus ones. The metadata page is a snapshot with a source comment added on the first line.

## What uses what

- `mpris/` is the input of `data/mpris-dbus-interface.xml`, generated by `scripts/gen-mpris-interface.py` and compiled by `gdbus-codegen` (`playerctl/meson.build`). `playerctl/gen-introspection-header.py` turns the same file into the introspection data `playerctld` announces (`mpris_introspection_xml`, built by `playerctl/meson.build`), leaving out `Player.GetArtworkFd`, which `playerctld` does not forward.
- `data/org._5mdt.playerctld.xml` is playerctld's own interface, not a vendored specification. It goes through the same generator and is installed to `share/dbus-1/interfaces`.
- `dbus/` defines `org.freedesktop.DBus.Properties` (`PropertiesChanged`, `EmitsChangedSignal`), `Introspectable`, `Peer` and the error names, which playerctl and `playerctld` rely on.
- `mpris-metadata/` defines the `xesam:*` and `mpris:*` metadata keys that `playerctl metadata` and the format strings read.

## Not vendored

GVariant, GObject Introspection and gtk-doc are documented with GLib and are build tools of the project, not specifications it implements. The Debian changelog (RFC 2822 dates) and shell completion conventions are used by the packaging, not by the program.
